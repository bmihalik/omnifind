## Add to an existing checkout

This example targets the omnifind public API at commit `b306c70af565816a41a469f7622959ac6798217e`. The archive is an add-on, not a replacement for the crate.

Recommended: extract the archive, then apply its patch from the omnifind repository root:

```sh
cd /path/to/omnifind
git apply --check /path/to/omnifind-cli-example/omnifind-cli.patch
git apply /path/to/omnifind-cli-example/omnifind-cli.patch
```

The patch adds `examples/cli.rs`, this guide, and only the needed Cargo.toml entries. If it cannot apply because the manifest changed, use the manual method instead; do not use both methods.

### Manual method

Copy `examples/cli.rs` and optionally `examples/CLI.md` into your checkout's `examples/` directory. Add the following line to the **existing** `[dev-dependencies]` section in Cargo.toml, keeping the existing Tokio entry:

```toml
clap = { version = "4.5", features = ["derive"] }
```

Append this target declaration at the end of Cargo.toml:

```toml
[[example]]
name = "cli"
path = "examples/cli.rs"
test = true
```

The explicit `test = true` makes `cargo test --all-targets` run the example's unit tests. Other dependencies (`futures`, `serde`, `serde_json`, `url`, and `tokio`) already exist in the crate; no library source changes are needed. No manual Cargo.lock edits are needed; let Cargo resolve dependencies according to your repository's lockfile policy.

Resulting layout:

```text

├── examples/
│   ├── basic.rs               # Existing example, unchanged
│   ├── cli.rs                 # New CLI and unit tests
│   └── CLI.md                 # This optional guide
```

## Build and run

From the repository root:

```sh
cargo fmt --all -- --check
cargo test --all-targets
cargo clippy --all-targets -- -D warnings
cargo run --example cli -- --help
cargo run --example cli -- search --help
```

Everything after Cargo's `--` goes to the CLI. Quote multi-word queries. Global flags can appear before or after the subcommand.

```sh
# Web search (default engine: duckduckgo; aliases: ddg and wiki)
cargo run --example cli -- search "Rust async programming" --engine wikipedia --limit 5

# Concurrent metasearch; limit is per engine, not a global result limit
cargo run --example cli -- meta "self hosted LLM" --engines duckduckgo,qwant,wikipedia -n 5

# Images and books
cargo run --example cli -- images "Budapest skyline" -n 8
cargo run --example cli -- books "The Hobbit" -n 5

# Extract a page's title, text, and links
cargo run --example cli -- extract https://example.com

# Machine-readable stdout; diagnostics go to stderr
cargo run --quiet --example cli -- --json books "Rust programming" -n 5 > books.json

# Per-request timeout and explicit proxy
cargo run --example cli -- --timeout 30 --proxy http://127.0.0.1:8080 search "Rust" -e wikipedia
```

`search` supports `duckduckgo`, `qwant`, and `wikipedia`; `images` uses DuckDuckGo, and `books` uses Open Library. Service-side caps can return fewer results than requested: the current library caps Wikipedia at 50, Qwant at 10, and Open Library at 100 per request. DuckDuckGo requests a single page; this CLI does not add pagination or retries.

## Output and errors

- Default output is readable text. Remote control characters and directional override/isolate characters are escaped for terminal display.
- `--json` writes the library's result array, or extracted-page object, using pretty JSON and a trailing newline. It does not write log messages to stdout.
- Metasearch calls `search` for each selected engine concurrently instead of the library's current failure-omitting `metasearch` convenience method. It reports failed engines as stderr warnings, removes repeated engine selections, and deduplicates exact result URLs while keeping paths and queries case-sensitive.
- If at least one engine succeeds, `meta` exits 0 even if others fail; successful zero-result searches also exit 0. JSON does not include a warning envelope: capture stderr separately if you need engine diagnostics.
- If all engines fail, or a single-engine/image/book/extraction request fails, the CLI exits 1. Usage errors exit 2. Normal help/version and downstream broken pipes exit 0.
- A positive timeout and result limit are required. Extraction accepts only absolute HTTP/HTTPS URLs. Proxy URLs accept HTTP, HTTPS, SOCKS4, SOCKS4a, SOCKS5, or SOCKS5h.
- Proxy credentials supplied on the command line may be visible in shell history, process listings, or underlying request errors. Avoid embedding credentials when sharing commands or diagnostics.
- This is an example client, not an SSRF-safe server endpoint. Only fetch URLs you trust. Page extraction uses the existing library behavior; it does not execute JavaScript or add article-readability algorithms.

HTTP 429, blocks, and endpoint changes remain real errors; this CLI does not bypass restrictions or hide live failures. No new live success claims are made for search engines by this example's tests.

## Release executable

```sh
cargo build --release --example cli
./target/release/examples/cli --help
```

On Linux/macOS, optionally copy it to a directory on your PATH:

```sh
mkdir -p "$HOME/.local/bin"
install -m 755 target/release/examples/cli "$HOME/.local/bin/omnifind"
omnifind --json books "The Hobbit" -n 3
```

Make sure `$HOME/.local/bin` is on PATH. On Windows the built example is `target/release/examples/cli.exe`.
