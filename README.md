# omnifind

`omnifind` is an asynchronous Rust crate for metasearch and web-content extraction. It uses [`primp`](https://crates.io/crates/primp) for browser-impersonating HTTP requests and presents normalized result types.

## Sources

- DuckDuckGo web and image search
- Qwant web search
- Wikipedia search
- Open Library book search
- Generic HTML title, text, and link extraction

Public endpoints can change or apply rate limits. Applications should handle partial results and comply with each source's terms, robots policies, and applicable law.

## Quick start

```rust
use omnifind::{Engine, Omnifind, Result};

#[tokio::main]
async fn main() -> Result<()> {
    let client = Omnifind::new()?;
    let results = client
        .metasearch(
            "local large language models",
            &[Engine::DuckDuckGo, Engine::Wikipedia],
            5,
        )
        .await?;

    for result in results {
        println!("[{}] {} — {}", result.source, result.title, result.url);
    }
    Ok(())
}
```

## API overview

- `search(engine, query, limit)` searches one backend.
- `metasearch(query, engines, per_engine)` runs backends concurrently and deduplicates URLs.
- `images(query, limit)` searches DuckDuckGo Images.
- `books(query, limit)` searches Open Library.
- `extract(url)` retrieves a page and extracts its title, readable text, and absolute links.
- `Omnifind::builder()` configures timeouts, proxying, and browser impersonation.

## Response decoding and diagnostics

The browser profile advertises `gzip`, `deflate`, `br`, and `zstd`; the matching `primp` decompression features are explicitly enabled. Disabling these features while keeping the profile's `Accept-Encoding` header can pass compressed bytes to a JSON parser.

JSON endpoints send `Accept: application/json`. Malformed or non-JSON responses return `Error::InvalidResponse` with the engine name, content type, and content encoding; response bodies are not included in diagnostics. Non-success HTTP responses remain `Error::Status`, including HTTP 429 rate limits. These errors are not treated as empty results or successful live tests.

Local HTTP fixture tests exercise all four compression encodings, identity JSON, HTML responses, and HTTP 429 without depending on external services. They do not prove public-service availability. In validation of this change, Open Library's live test passed, while Wikipedia returned HTTP 429 from the test environment; Wikipedia live success therefore remains unverified.

## Marginalia

Marginalia is available as `Engine::Marginalia` in `search()` and `metasearch()`;
`Engine::ALL` now includes four engines. Adding this enum variant requires updating
any downstream exhaustive `match` expressions. Source tags are `"marginalia"`.

The adapter uses the current API at `https://api2.marginalia-search.com/search`,
with `query` and `count` query parameters and an `API-Key` header. No API key is
placed in the URL or other engines' default headers. A separate HTTP client
copies the configured timeout/proxy/impersonation settings and refuses redirects
to prevent forwarding the custom credential header.

```rust,no_run
use omnifind::{Engine, Omnifind, Result};

# async fn example() -> Result<()> {
let client = Omnifind::builder()
    .marginalia_api_key("YOUR_KEY")
    .build()?;

// Recommended: preserve the upstream license notice, even for zero matches.
let response = client.marginalia("small web", 5).await?;
println!("License: {:?}", response.license);
for row in response.results {
    println!("{} — {}", row.title, row.url);
}

// Generic normalized API is also supported, but drops response-level metadata.
let rows = client.search(Engine::Marginalia, "small web", 5).await?;
# let _ = rows;
# Ok(())
# }
```

No key configured means the documented shared `public` **experimental** key.
For sustained use obtain your own key. The library intentionally does not read
environment variables; applications can pass them to the builder. The executable
example reads `MARGINALIA_API_KEY` explicitly:

```bash
MARGINALIA_API_KEY='YOUR_KEY' cargo run --example marginalia -- "small web"
```

Counts are capped at 100 per request; there is no automatic pagination, retry, or
HTML-scraping fallback. A zero limit performs no HTTP request and returns
`license: null`, rather than an invented notice. Non-success statuses (including
429/503) and malformed response schemas are errors. Existing `metasearch()` still
omits failed engines; query `marginalia()` directly for explicit errors and license
metadata. The ordinary `SearchResult` shape is unchanged.
